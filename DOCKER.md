## Что уже подготовлено

| Файл | Назначение |
|---|---|
| `Dockerfile` | Основа Python 3.12, установка библиотеки Excel, копирование кода и запуск консольной программы |
| `requirements.txt` | Общие зависимости для локального запуска и контейнера |
| `.dockerignore` | Исключает окружения Python, личные данные, отчёты и кэши из контекста сборки |
| `compose.yaml` | Описывает сборку, интерактивный ввод и общую папку `data` |
| `run_docker.bat` | Необязательный ярлык: создаёт именованный контейнер или повторно открывает его |
| `verify_docker.py` | Собирает образ и проверяет расчёт и сохранность SQLite между двумя контейнерами |

`Dockerfile` — рецепт сборки. **Образ** появляется после успешного `docker build`.
**Контейнер** создаётся командой `docker run` или `docker compose run` из этого образа.
Наличие одного Dockerfile не доказывает, что программа запускалась в Docker.

## Ручная сборка и запуск для защиты

Для Windows нужен установленный и запущенный [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/).
В его настройках используется движок Linux-контейнеров. Дождитесь готовности движка.
Проверка в PowerShell:

```powershell
docker version
docker compose version
```

В `docker version` должны отвечать и Client, и Server. Только установленного клиента недостаточно.

Сборку выполняет Docker. Команды вводятся в PowerShell; батник для лабораторной
не обязателен. Перейдите в папку с Dockerfile:

```powershell
cd "D:\Desktop\Арина\3 курс\lab_2"
New-Item -ItemType Directory -Force data | Out-Null
docker build -t recipes-lab:local .
```

Точка означает текущую папку как контекст сборки. Docker читает Dockerfile,
подготавливает Python 3.12, устанавливает requirements.txt и копирует программу.
Результат сборки — образ recipes-lab:local; контейнер на этом шаге ещё не запускается.

При первом создании контейнера:

```powershell
docker run -it --name recipes-lab-app --mount "type=bind,source=${PWD}\data,target=/app/data" recipes-lab:local
```

`-it` подключает интерактивную консоль, `--name` задаёт имя, `--mount` подключает
папку данных. В том же терминале открывается меню калькулятора. Повторно нажимать
Start в Docker Desktop не требуется. После пункта 0 контейнер остановится и сохранится.

Команда run создаёт новый контейнер и нужна только один раз для данного имени.
Сейчас recipes-lab-app уже создан и проверен. Для следующего запуска используйте:

```powershell
docker start -ai recipes-lab-app
```

`-a` подключает вывод, `-i` подключает ввод. При таком запуске команды меню вводятся
в этот же PowerShell. Docker Desktop показывает состояние контейнера.
Если включён фильтр Only show running containers, выключите его для просмотра
остановленного контейнера. Кнопка Start в Desktop не открывает отдельное окно Windows;
для интерактивного показа используйте start -ai в терминале.

Батник run_docker.bat оставлен как необязательный ярлык. Он создаёт тот же контейнер
при первом запуске и повторно открывает его при следующих. Автоудаление отключено.
При уже работающем контейнере батник сообщает об этом и не создаёт ещё один экземпляр.
Файл compose.yaml — дополнительная конфигурация; для ручного показа он не требуется.

После изменения кода образ нужно собрать заново и создать новый контейнер из нового
образа. Команда start запускает уже существующий контейнер с ранее скопированным кодом.

## Где находятся база и отчёты

`compose.yaml` подключает папку проекта `data` к `/app/data` контейнера.
В ней остаются `recipes.sqlite3` и `reports/*.xls`. Поэтому история и отчёты
сохраняются после выхода и удаления контейнера. Это SQLite-файл, отдельный
сервер базы данных для данной лабораторной не нужен.

Ручной запуск и батник теперь сохраняют контейнер. Образ и общая папка данных
также остаются. Для просмотра всех контейнеров, включая остановленные:

```powershell
docker ps -a --filter name=recipes-lab-app
docker image ls recipes-lab
```

Флаг --rm используется только в отдельной автоматической проверке verify_docker.py,
чтобы удалять её временные контейнеры. Сохранённый recipes-lab-app она не удаляет.

## Проверка для защиты

```powershell
.\.venv\Scripts\python.exe verify_docker.py
```

Сценарий проверяет работающий движок, собирает образ, запускает первый контейнер,
рассчитывает пиццу и сохраняет SQLite и `.xls`. После удаления первого контейнера
второй контейнер читает ту же базу и проверяет 870 ккал, 150 руб. и формат Excel.
Он не использует личную историю: создаёт отдельную папку `.qa/docker-*`.

Журнал сохраняется в `docs/docker-verification.txt`. Только итог `PASS` означает
успешную реальную проверку. `NOT RUN` означает, что проверка не запускалась,
а `FAILED` — что она не завершилась успешно. Сейчас результат — `PASS`.

Для отчёта после успешной проверки приложите журнал и снимки сборки,
работающей программы, списка образов и содержимого папки с SQLite и отчётом.

Документация: [Dockerfile и сборка](https://docs.docker.com/build/concepts/dockerfile/),
[docker run](https://docs.docker.com/reference/cli/docker/container/run/),
[docker start](https://docs.docker.com/reference/cli/docker/container/start/),
[bind mounts](https://docs.docker.com/engine/storage/bind-mounts/).

Батник и скрипт умеют находить per-user установку Docker Desktop, даже если PATH
открытого терминала ещё не обновился. После установки можно также открыть новый терминал.
