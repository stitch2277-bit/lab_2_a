# Калькулятор рецептов

Репозиторий: [https://github.com/stitch2277-bit/lab_2_a](https://github.com/stitch2277-bit/lab_2_a).

Лабораторная работа №2 «Модули и пакеты Python. ООП».
**Вариант 9 по порядку — «Рецепты»**: вок, бургер, пицца.
В методичке эта строка помечена №11: после 7 идут 10 и 11.

Основа работы — пакет с тремя модулями, классы и тесты. Программа рассчитывает
калорийность и стоимость ингредиентов, сохраняет SQLite и экспортирует настоящий .xls.
Единое консольное меню работает и локально в Windows, и внутри Docker.

## Docker

**Docker установлен и проверен: Docker Desktop 4.99.0, Engine 29.9.3, Compose 5.7.0.
Образ recipes-lab:local собран. Реальная проверка двух контейнеров завершилась PASS;
требования Well-done по SQLite и Docker подтверждены.**

Подготовлены Dockerfile, compose.yaml, run_docker.bat и verify_docker.py.
Dockerfile устанавливает зависимости внутри образа до запуска программы.
Compose подключает папку data к /app/data: SQLite и отчёты переживают удаление контейнера.

Для защиты выполните команды Docker вручную в PowerShell из папки проекта:

    docker version
    New-Item -ItemType Directory -Force data | Out-Null
    docker build -t recipes-lab:local .
    docker run -it --name recipes-lab-app --mount "type=bind,source=${PWD}\data,target=/app/data" recipes-lab:local

Первая команда собирает образ, вторая создаёт и запускает контейнер с консольным меню.
Команда New-Item подготавливает папку data, не удаляя существующие файлы.
Контейнер остаётся после выхода из меню. В Docker Desktop выключите фильтр
«Only show running containers», чтобы видеть и остановленные контейнеры.
Команда docker run нужна один раз; для повторного запуска сохранённого контейнера:

    docker start -ai recipes-lab-app

Необязательный run_docker.bat создаёт такой же контейнер при первом запуске,
а затем открывает существующий. Локально и в контейнере используются одни main.py
и requirements.txt. После изменения кода образ нужно пересобрать, а контейнер
создать заново по инструкции DOCKER.md.
При первой сборке нужен интернет для базового образа и пакетов.

Проверка сборки, расчёта и SQLite между двумя контейнерами:

    python verify_docker.py

Итог — в docs/docker-verification.txt. Последняя реальная проверка: PASS.
Только реальный PASS подтверждает контейнерную часть. Сценарий использует отдельные
данные .qa/docker-* и не меняет личную историю. Подробности: [DOCKER.md](DOCKER.md).

## Локальный запуск

Проверено на Python 3.12:

    python -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements.txt
    .\.venv\Scripts\python.exe main.py

Можно открыть run.bat. Меню, ввод и результаты находятся в одном окне консоли.
При ошибке батник показывает её и ждёт нажатия клавиши, чтобы окно не закрылось сразу.
Для Linux/macOS используется .venv/bin/python.

## Краткая справка

Главное меню:

    1. Новый рецепт
    2. Демонстрационный расчёт
    3. История расчётов
    4. Сохранить текущий расчёт в Excel
    5. Справка
    6. О программе
    0. Выход

В пункте 1 выберите блюдо, задайте название, число порций и количество ингредиентов.
Для каждого продукта введите название, массу в граммах, ккал на 100 г и цену
в рублях на 100 г. Итоги появятся в консоли и автоматически сохранятся в SQLite.
Пункт 3 показывает последние 20 расчётов; введите номер, чтобы открыть результат.
Пункт 4 сохраняет текущий расчёт или открытую запись в настоящий .xls.
Enter выбирает предложенный путь; перед перезаписью существующего файла нужно согласие.

Точка и запятая допускаются. Масса больше нуля, цена и ккал неотрицательны;
числа до 1000000 с четырьмя десятичными знаками, порций и ингредиентов от 1 до 1000,
названия до 100 символов. При ошибке программа объясняет причину и повторяет запрос.

Справка доступна из пункта 5 или по команде «?» / «справка» при вводе.
«О программе» — пункт 6. «назад» / «отмена» возвращает в меню;
«выход» / «exit», Ctrl+C или пункт 0 завершает программу.
Если запись в SQLite не удалась, результат остаётся доступен для экспорта в текущем сеансе.

Пример без ручного ввода:

    python main.py --demo pizza --export data/pizza.xls
    python main.py --guide

## Формулы и контрольный пример

    Ккал ингредиента = масса × ккал_на_100г / 100
    Стоимость ингредиента = масса × цена_на_100г / 100
    Общий показатель = сумма вкладов ингредиентов
    На порцию = общий показатель / число одинаковых порций
    Ккал на 100 г = общие ккал × 100 / общая масса

Учебная пицца: тесто 200 г (250 ккал, 20 руб. на 100 г), сыр 100 г (350 ккал, 80 руб.),
томаты 100 г (20 ккал, 30 руб.). Всего 400 г, 870 ккал, 150 руб.; на одну из двух порций
200 г, 435 ккал, 75 руб.; на 100 г — 217,5 ккал.

Используется Decimal; округление ROUND_HALF_UP до двух знаков выполняется при выводе.
Не учитываются потери массы при готовке, целые упаковки, доставка, электричество,
работа повара и наценка. Данные примеров условные.

## Структура, тестирование и сдача

recipes/models.py содержит классы и формулы, storage.py — CalculationStore и SQLite,
reports.py — вывод и Excel. `__init__`.py обозначает пакет. main.py — основной запуск
и консольное меню для обоих способов запуска.
SQL параметризован, Decimal хранится в JSON строкой. У каждого класса есть `__init__` и `__str__`.

    .\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
    .\.venv\Scripts\python.exe -m pytest -q

Проверяются формулы трёх блюд, свойства и наследование, SQLite после повторного открытия,
настоящий .xls, консольный ввод, справка, отмена, выход и запуск батника Windows.
Docker проверяется отдельно verify_docker.py; локальные тесты не заменяют запуск контейнера.
